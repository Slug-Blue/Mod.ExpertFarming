## 1. Definition of Done для задачи

Задача закрыта, только если выполнено всё:

1. **Ветка** `feat/<id>-<slug>` от `main` (пример: `feat/wr-105-meiosis`). Spike — та же схема (`feat/wr-020-spike-s1-line-packs`), но его код **не мержится**: в `main` попадает только правка ADR или раздела документа с итогом (`05-architecture.md` §20.2: «код выбрасывается»).
2. **Коммиты — Conventional Commits** (`feat:`, `fix:`, `test:`, `docs:`, `build:`, `ci:`, `refactor:`, `chore:`), в теле — ID задачи. Push и PR — только после подтверждения владельца (`STATUS.md`, «Блокеры»).
3. **Зелёные локально и в CI:** `./gradlew build` (включает `:genetics:test`, `:mod:test`, ArchUnit) и `./gradlew :mod:runGameTestServer`. С фазы 7 — ещё job `gametest-offline` (SEC-44).
4. **Все критерии приёмки** задачи проверены; в описании PR — список критериев с отметкой и ссылкой на тест (класс и метод) или на запись ручной проверки.
5. **Тесты** написаны или проверены Test Automation Engineer: каждый критерий «JUnit»/«GameTest» — это тест в репозитории, а не ручной прогон. Статистика — с фиксированным сидом.
6. **Ревью Code Reviewer** без открытых замечаний уровня «блокер». Изменения `verification-metadata.xml`, `accesstransformer.cfg`, `wildroots.mixins.json`, workflow-файлов — дополнительно ревью DevOps (SEC-40, SEC-45).
7. **Безопасность:** если задача касается строки таблицы SEC (§8.3), её проверка выполнена; новые точки входа обёрнуты в `Guarded.run` (SEC-34); новые C→S пакеты зарегистрированы только через `ServerPacketGuard` (SEC-01).
8. **Тексты:** новые ключи есть в `en_us.json` и `ru_ru.json`; строки прошли чек-лист `04-narrative.md` §10.3. Хардкод строк в коде нет.
9. **Без сюрпризов:** нет новых зависимостей без ADR и PR с `verification-metadata.xml` (§18 архитектуры); нет новых mixin вне списка M1–M7 (ADR-0014); нет сетевых API (SEC-43).
10. **Документы:** если реализация уточнила поведение, правка внесена в раздел спецификации или в ADR в том же PR (или открыт вопрос оркестратору).

## 3. Фаза 4: каркас

Цель: пустой мод `wildroots` собирается, запускается и тестируется в CI с защитой цепочки поставок. Ни одной игровой механики. Источники: архитектура §3, §17, §18; ADR-0001, ADR-0014, ADR-0016; `09-security.md` §1.6.8, §1.7; SEC-37…SEC-45.

### WR-001 · Проверить `.gitignore` и `.gitattributes`
Фаза 4 · — · GWM · 0.5 д
Ссылки: задание фазы 4; `STATUS.md`.
Сейчас в `.gitignore`: `.gradle/`, `build/`, `out/`, `run/`, `runs/`, IDE-файлы. В `.gitattributes`: `* text=auto eol=lf`, `*.png`, `*.ogg`, `*.jar` — binary.
Приёмка:
- `git check-ignore` подтверждает игнор для каталогов, которые создаёт MDK 47.x и ForgeGradle 6 (`build/`, `.gradle/`, `run/`, `bin/`, `logs/`, `src/generated/resources/.cache/` — список сверяется с `.gitignore` из MDK, недостающие строки добавляются).
- `gradle/wrapper/gradle-wrapper.jar` **не** игнорируется и коммитится (проверка `git ls-files`).
- `git ls-files --eol`: `gradlew` — `lf`, `gradlew.bat` — `crlf` (добавить `*.bat text eol=crlf`); структурные шаблоны `*.nbt` помечены `binary` (нужны GameTest и `old_save_vN`, архитектура §5.4).

## 9. Критический путь

**До шлюза M1a** (при достаточном числе исполнителей на параллельные ветви):

```
WR-001 → WR-002 → WR-004 → WR-006 → WR-007 → WR-026 (S7)
  → WR-101 → WR-102 → WR-104 → WR-107 → WR-113
  → WR-125 → WR-131 → WR-150 → WR-151 → WR-152 → WR-195
```

0.5 + 1 + 0.5 + 1 + 1 + 1 + 1 + 1 + 1.5 + 1 + 0.5 + 2 + 1.5 + 2 + 1.5 + 2 + 1.5 = **21.5 рабочего дня**.

Почти критические ветви (запас ≤ 1.5 д): `WR-131 → WR-140 → WR-141 → WR-142 (+ S2) → WR-195` (4 д против 5.5 у worldgen-ветви); `WR-020 (S1) → WR-124 → WR-150` (S1 должен закончиться до конца WR-125); `WR-028 (S9)` — до WR-195. Для WR-131 нужен WR-125 (снимок определений), поэтому задержка загрузчика сдвигает всю волну.

**До кандидата релиза волны 1:** M1b идёт параллельно с конца M1a-ветвей; самые длинные хвосты — `WR-142 → WR-187 → WR-199` и `WR-164 → WR-165`. Оценка: ≈ 25 рабочих дней по критическому пути; суммарная трудоёмкость волны 1 — 97.5 чел.-дня, что при 4 параллельных исполнителях кода даёт ≈ 25–30 рабочих дней. Перед ней: фаза 4 (14.5 д, критический путь ≈ 6 д) и spike (17.5 д, параллельно, ≈ 5 рабочих дней при 4 исполнителях; архитектура закладывает неделю). Плюс фазы 6–10 для волны 1 — ≈ 27 д трудоёмкости, ≈ 12–15 рабочих дней по цепочке WR-604 … WR-612.

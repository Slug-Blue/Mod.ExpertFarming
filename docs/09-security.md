# Часть 1. Threat model (фаза 2)

## 1.1 Область и допущения

**В области:** серверная логика мода (`:genetics`, `:mod`), сетевой канал `wildroots:main`, ванильные пакеты, на которые опирается мод (контейнеры, `clickMenuButton`, слот креатива, торговля), декодеры NBT (предметы, BlockEntity, capability, SavedData, шаблоны структур), загрузчики JSON из датапаков, интеграции (FD, JEI, EMI, Jade, WTHIT), mixin и AT, сборка и CI.

**Вне области:**
- Злонамеренный мод в той же JVM. У него полные права, и защищаться от него бессмысленно.
- Уязвимости самого Minecraft, Forge, Netty и JVM. Мод их не усугубляет, и это всё, что он может сделать.
- Античит общего назначения (полёт, x-ray, kill-aura).
- Одиночная игра: игрок и есть оператор. Требования к устойчивости (без краша) там всё равно действуют.

**Допущения:** мод стоит на сервере и на клиенте (протокол `"1"`, §14 архитектуры). Сервер выделенный, на нём от 2 до 50 игроков. Оператор доверенный, но может ошибиться в конфиге. Датапаки ставит оператор, но пишет их кто угодно: авторы модпаков, карты из интернета.

## 1.2 Активы

| # | Актив | Почему ценен | Где живёт |
|---|---|---|---|
| A1 | **Доступность сервера** (TPS ≤ 50 мс, нет крашей) | Видение: ≤ 2 мс MSPT на 10 000 растений | Тик сервера |
| A2 | **Возможность войти и открыть контейнер** | «Inventory ban» или «chunk ban» хуже краша: игрок не может зайти, пока оператор не вычистит NBT | Пакеты S→C |
| A3 | **Целостность мира и сохранений** | Геномы — результат часов селекции. Требование «старое сохранение грузится» | BE, NBT предметов, SavedData |
| A4 | **Сохранение предметов** (нет дюпа и нет потери) | Лоты уникальны. Дюп обесценивает селекцию, потеря злит игроков | Меню, мешочек, торговля |
| A5 | **Экономика** (изумруды, уникальность редких находок, деревенский фонд) | Кран селекционера ≤ 6 находок в день (economy §6.5), фонд деревни ограничен полем (П16) | Торговля, деревни |
| A6 | **Лестница информации** (тиры 0–3) | Сердце дизайна «фенотип, а не цифры» (GDD §10) | NBT лота, анализатор, Jade |
| A7 | **Контент игроков** (имена сортов яблони, имена линий) | Его видят другие игроки, и он бьёт по репутации сервера | `wildroots_named_selections`, `line_name` |
| A8 | **Целостность jar и цепочки сборки** | Jar запускается на тысячах машин | Gradle, Maven, GitHub Actions |
| A9 | **Машины игроков** | Мод не ходит в сеть и не выполняет внешний код (метрика 7) | Клиент, сервер |
| A10 | **Секреты CI** (токены Modrinth и CurseForge) | Через них можно опубликовать вредоносный релиз | GitHub secrets |
| A11 | **Секрет мира** (новый, SEC-25) | Не даёт предсказать потомство | `SavedData` `wildroots_secret` |

| Граница | Что пересекает | Доверие к данным |
|---|---|---|
| **B1** клиент → сервер | Наши C→S пакеты, ванильные клики и use-пакеты | **Нет.** Клиент сообщает только намерение («кликнул слот 5», «назвать выборку 17»). Всё остальное сервер выводит сам |
| **B1c** слот креатива | `ServerboundSetCreativeModeSlotPacket`: ванилла принимает **любой** `ItemStack` с любым NBT от игрока в креативе | **Нет.** Это единственный путь, по которому клиент кладёт на сервер NBT лота. Дизайн это допускает (креатив = «бог»), но декодеры обязаны его пережить |
| **B1j** запрос Jade/WTHIT | Позиция блока или сущности от клиента | **Нет**: позиция может быть любой, в том числе в выгруженном чанке |
| **S→C** | Полный NBT предметов, `BlockState`, наши пакеты | Клиент видит всё, что ему отправили (§1.8) |
| **B2** датапак → загрузчик | JSON | **Частичное.** Ставит оператор, но ошибки и «бомбы» возможны. Обязательна мягкая валидация |
| **B3** NBT с диска и из шаблонов | Сохранения, `.nbt` структур, миры другой версии | **Частичное.** Формат может быть старым, будущим, повреждённым или подделанным |
| **B4** сторонний мод → мы | Вызовы capability, события, перенос блоков, копирование NBT | Код доверенный, но поведение непредсказуемое. Инварианты проверяем у себя |
| **B5/B6** | Артефакты сборки, workflow, секреты | Проверяются checksum'ами, закреплением версий и ручным релизом (§1.7) |

## 1.8 Оценка решения «геном лота виден модифицированному клиенту» (§21 п. 6 архитектуры)

**Что получает злоумышленник.** Только **информацию**, не целостность. Сервер всё равно решает потомка, класс и сорт, и подделать лот в survival нельзя (B1c — только креатив). Конкретно:

1. Генотип своих лотов (тир 3 без лаборатории): носители, S-аллели, груз. Обход лестницы информации GDD §10.
2. Генотипы чужих лотов, которые он видит: в руке другого игрока, на земле, в открытом общем сундуке. Для кооперативного мода это неважно. Для соревновательных серверов («кто первым выведет сорт») это мелкая нечестность.
3. **Без SEC-25 — оракул потомства (T-I2).** Мод на клиенте с открытым алгоритмом движка считает точного потомка для каждой клетки и сажает семя туда, где выпадет лучшее. Это сильнее любой легальной информации и ломает темп селекции (GDD §12). **С SEC-25** у клиента нет секрета, и он знает только распределение, то есть ровно прогноз лаборатории.

**Вердикт: приемлемо при условии SEC-25** (серьёзность падает с Medium до Low). Аналоги в ванилле — x-ray и взлом сида: информационное читерство без вреда другим и без порчи мира. Мод кооперативный, PvP-экономики нет, изумруды игрок получает только от жителей.

**Альтернативы** (если владелец захочет «сервер скрывает»):

| Вариант | Скрывает | Цена | Рекомендация |
|---|---|---|---|
| А. Как сейчас + SEC-25 | Нет (только исход посадки) | ≈ 0 | **Да, для MVP** |
| Б. `getShareTag` урезает геном | Да | Креатив стирает геномы (§6.3); нужен серверный кэш `lotId → геном` без сборки мусора | Нет |
| В. Шифровать геном в NBT: AES-GCM ключом из `wildroots_secret` (JDK `javax.crypto`, без новых зависимостей) | Да; **плюс** аутентичность: подделанный в креативе геном не проходит тег и становится инертным | +28 байт на геном (nonce 12 + tag 16), мешочек ≈ +3.5 КиБ (укладывается в 16 КиБ); ≈ 1–2 мкс на расшифровку; предметы **привязаны к миру**: в другом мире они инертны до возврата (данные не теряются, §5.3); перенос между мирами одной сети серверов требует общего ключа в конфиге | Отложить; вернуться, если появятся соревновательные серверы или жалобы на «WR-x-ray» |
| Г. Хранить геном только на сервере (`SavedData` по `lotId`), в предмете — ссылка | Да | Рост мира без GC, лоты в сундуках чужих миров теряют геном, нарушение «геном внутри предмета» (GDD §14) | Нет |

Растения в мире геном клиенту не отдают (§6.1 архитектуры), и Jade ограничен SEC-08. Здесь «сервер скрывает» соблюдено.

## 1.11 Вопросы к владельцу

1. **Геном лота виден модифицированному клиенту**: принять вариант А + секрет мира (рекомендую) или требовать шифрование (вариант В, предметы привязываются к миру)?
2. **Мешочек нельзя положить в шалкер или bundle** (отличие от ванильного bundle; без этого survival-грифер может «забанить» сундук или инвентарь). Принять? (рекомендую да)
3. **Имя сорта яблони:** только буквы, цифры, пробел и `- ' ’ . , ( ) &`, без эмодзи, ≤ 24 символа; имя задаётся один раз, оператор может переименовать или очистить командой. Принять? (да)
4. **Что падает с молодого растения, если его сломать** (против reroll, SEC-26): ничего или «росток» с уже определённым геномом? (рекомендую ничего на стадии 0, росток с реализованным геномом на стадии 1; решает Game Designer)
5. **Потолок находок считается окнами по 20 минут игрового времени**, а не по смене дня (сон не сбрасывает). Нужен ли дополнительно общий потолок на мир против мультиаккаунтов? (окна — да; общий потолок — выкл. по умолчанию)

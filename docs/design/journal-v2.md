**Что не так с журналом v1 (по коду `JournalScreen` / `JournalPages`):**

1. Ванильная одностраничная книга 192 × 192 и столбик кнопок-вкладок слева, вне книги. Нет оглавления: вкладка открывает первую страницу ленты, дальше только `<` `>`.
2. Только текст. Ни одной иконки предмета, ни рецепта, ни картинки стадии. Всё, что игрок должен «увидеть», ему пересказано словами.
3. Каждый блок — с новой страницы, длинный блок режется по 14 строк без учёта смысла. Вкладка «Заметки» — это 20+ страниц подряд.
4. Нет поиска, истории, ссылок между записями. Закрепление (`+`/`-`) есть, но выглядит как отладочная кнопка.
5. Журнал учит только тому, что игрок уже сделал (подсказки по триггерам). Справки «как устроено» нет совсем: рецепт лупы, цикл маточника, смысл шкалы лупы игрок узнаёт из подсказок вразнобой или не узнаёт.

## 1. Образцы: что берём

Разбор по памяти, без загрузок. Сначала — что делает каждую книгу удобной, потом — 8 приёмов, которые переносим.

Рецепты и мультиблоки рисуются живыми из игры, а не картинками. Наведение на предмет на странице даёт ванильный тултип, клик ведёт на его запись. ## 2. Информационная архитектура

### 2.1 Два слоя: «Руководство» и «Мои записи»

Narrative §4.1: журнал — «учебник, который не выглядит учебником; записывает увиденное и добавляет шаг вперёд». v2 сохраняет это и добавляет справку:

- **Руководство** (статичное, в ресурсах клиента) — «как устроено»: стадии, цикл маточника, лупа, отбор, опыление. Голос тот же — натуралист, без приказов (narrative §1.1). Каждая статья открывается, когда игрок уже столкнулся с темой (§2.3), поэтому это всё ещё «шаг вперёд от увиденного».
- **Мои записи** (динамические, от сервера через `JournalSync`) — виды, сорта, линии, заметки-подсказки, записки селекционера. Как в v1, но в новом каркасе.

Связь слоёв: каждая заметка-подсказка ведёт ссылкой «Подробнее» на статью руководства (таблица §4.3); статья руководства показывает блок «Твои записи по теме» — открытые подсказки этой темы.

### 2.2 Категории → записи → страницы

```
Журнал
├─ Титул (владелец, дата первой записи) ─ всегда
├─ Оглавление (разворот с иконками) ─ всегда
│
├─ РУКОВОДСТВО (статичное)
│  ├─ Первые шаги        guide.start, guide.journal, guide.seed_lot
│  ├─ Растение и урожай  guide.stages, guide.mother_root, guide.cycle
│  ├─ Лупа и признаки    guide.lens, guide.traits, guide.colors
│  ├─ Отбор и опыление   guide.selection, guide.pollination, guide.inbreeding
│  ├─ Сорта              guide.cultivars
│  └─ Инструменты        guide.tool.field_journal, guide.tool.hand_lens, guide.tool.seed_pouch, (M1b) …
│
└─ МОИ ЗАПИСИ (динамическое, JournalSync)
   ├─ Виды       сетка открытых видов → страница вида (species.*)
   ├─ Сорта      коллекция: открытые и силуэты (cultivar.*)
   ├─ Линии      родословные (cultivar.* с рядами line; M1b: line.*)
   ├─ Заметки    подсказки (hint.*), новые и закреплённые сверху
   └─ Записки селекционера (note.*) — волна 2, в волне 1 скрыта
```

**Вкладка «Инструменты» v1 сливается с руководством.** Запись сервера `tool.<id>` больше не отдельная страница: она открывает статью `guide.tool.<id>` раньше времени (если та ещё закрыта), ставит «Новое» и метку «Есть у тебя» на витрине. Текст `wildroots.journal.tool.<id>` переходит на первую страницу статьи. Решение владельца В5.

**Запись** — то, что видно в оглавлении категории одной строкой с иконкой. **Страница** — половина разворота. Запись из 1–6 страниц; запись, которой нужно больше, делится на две.

### 2.3 Открытие и спойлеры

Правило одно: **клиент показывает статью руководства, только если у него есть запись сервера, которая её открывает** (`unlock` в JSON, §5.3). Клиент ничего не вычисляет о генетике: он смотрит на id и флаги записей, которые сервер уже прислал (`ClientJournal`). Это совместимо с текущими правилами подсказок (narrative §4.1, `JournalHints`): подсказка поздней волны не срабатывает → её статья не открывается.

| Состояние статьи | Условие | Как выглядит |
|---|---|---|
| Открыта всегда | `unlock: []` (только «Первые шаги», «Как читать журнал», рецепты стартовых инструментов) | Обычная строка |
| Закрыта | Ни одной записи из `unlock` нет | **Не показывается совсем** (ни строкой, ни замком). Категория без открытых статей скрыта |
| Открыта | Есть хотя бы одна запись из `unlock` | Строка в оглавлении |
| Новая | Хотя бы одна открывшая её запись сервера несёт флаг `NEW` | Зелёная метка «Новое» (`wildroots.journal.ui.new`) у статьи, категории и в оглавлении |
| Страница внутри статьи | У страницы может быть свой `unlock` | Закрытая страница просто пропускается (так «оранжевый корень» не виден до `hint.orange_root`) |

- **`showAllGuides`** (В4) — клиентская опция (`config/wildroots-client.toml`, по умолчанию `false`). `true` открывает все статьи и страницы руководства, как в IE; динамические записи она не трогает (их по-прежнему присылает сервер). Тексты статей и так лежат в jar, так что опция ничего не раскрывает сверх того, что уже на диске игрока.
- **Динамические записи** — по правилам v1: вид скрыт до `SpeciesDiscovered`; сорт — силуэт и `???` с целью после открытия вида, полностью — после `CultivarBred` (narrative §4.4); виды и сорта выключенных линий не приходят вовсе.
- **Прочитано.** Для динамической записи — как в v1: `JournalAction MARK_READ` при первом показе её страницы. Для статьи руководства своего «прочитано» нет: она «новая», пока «новая» открывшая её запись; открыв статью, клиент отправляет `MARK_READ` за эти записи (они в журнале игрока, сервер их примет). Отдельного хранилища не нужно.
- **Чисел нет** в тирах 0–1 (narrative §1.2 п. 2): сцены и их подписи пишут «лот семян», а не «3 + 9·P семян»; номер стадии есть только в данных сцены.
- **Модифицированный клиент** может прочитать все статьи из jar — это не утечка: в них нет порогов, частот и элитных локусов (SEC-04, T-I4). Секретное остаётся на сервере, как и сейчас.

### 2.4 Ссылки

Три вида, все — переход внутри книги с записью в историю:

1. **Ссылки в тексте** — только в ключах руководства (`wildroots.journal.guide.*`): разметка `[[guide.cycle|цикл маточника]]`. Парсер клиента превращает её в подчёркнутый текст цвета ссылки. Ссылка на закрытую статью рисуется обычным текстом без подчёркивания (не спойлерит и не ведёт в пустоту). В серверных ключах (подсказки, виды, сорта) разметки нет: так текст подсказки в тосте и в других местах остаётся чистым.
2. **Иконки предметов** на страницах: клик ведёт на статью, у которой этот предмет в `items` (П3). Наведение — ванильный тултип.
3. **Ряд «См. также»** внизу последней страницы статьи и «Подробнее →» на заметке-подсказке (таблица §4.3).

## 3. Типы страниц и макеты

### 3.0 Каркас: разворот

Книга — **разворот 288 × 180** (GUI-пикселей) плюс полоса навигации 16 под ним и закладки-вкладки, выступающие на 12 слева. Итого 300 × 200: влезает в наименьшее окно, которое Minecraft допускает при любом масштабе (масштаб выбирается так, чтобы окно было не меньше 320 × 240). Отдельный «узкий» режим не нужен.

```
   ┌─┐┌────────────────────────────────────┬───────────────────────────────────┐
   │▣││ ◄ Растение и урожай          [★]   │                              2 / 6│
   ├─┤│                                    │                                   │
   │▣││  Левая страница                    │  Правая страница                  │
   ├─┤│  116 × 148, 16 строк по 9 px       │  116 × 148                        │
   │▣││                                    │                                   │
   ├─┤│                                    │                                   │
   │▣││                                    │                                   │
   └─┘│                                    │                                   │
      └────────────────────────────────────┴───────────────────────────────────┘
       [◄◄ назад]  [◄]   [⌂ Оглавление]   [🔍 поиск______]   [►]  [вперёд ►►]
```

- **Слева — вкладки-закладки** категорий (иконки 16 × 16, до 8 по 20 px; у категории с новым — зелёная точка). Под ними — пользовательские закладки (§3.10), лентой другого цвета.
- **Шапка левой страницы:** «◄» к родителю (оглавление категории), название записи, звезда закладки. **Шапка правой:** номер разворота.
- **Полоса навигации:** история назад/вперёд, листание, оглавление, поле поиска.
- Текст — цвет чернил `0x3A2A1A` на бумаге, заголовки жирные, ссылки `0x2B5C8A` с подчёркиванием при наведении, «Новое» — `0x2E7D32` (как в v1).
- Всё, что наводится, даёт тултип; всё, что кликается, подсвечивается рамкой при наведении и фокусе клавиатуры.

### 3.1 Текст + витрина предмета (`spotlight`)

Одна мысль, один предмет крупно (П6). Предмет — живой `ItemStack` из реестра; для вариантов (жёлтая/фиолетовая восточная морковь) — стек для показа, собранный на клиенте, он никуда не отправляется.

```
┌──────────────────────────────┐
│ Маточник                [★]  │
│                              │
│          ┌────────┐          │
│          │  ▓▓▓▓  │  ← предмет 2× (32 px),
│          │  ▓▓▓▓  │    тултип при наведении
│          └────────┘          │
│     Маточник моркови         │  ← имя предмета
│  ✓ Есть у тебя               │  ← только если есть tool.* / предмет в инвентаре
│ ──────────────────────────── │
│ Сбор на урожайной зрелости   │
│ даёт еду и маточник. Маточ-  │  ← до 8 строк; больше — следующая страница `text`
│ ник — то же растение: поса-  │
│ женный, он зацветёт и даст   │
│ семена.  [[guide.cycle|Цикл]]│
└──────────────────────────────┘
```

Поля: `item` (id), `variant` (необязательный ключ показа: `colour=yellow` и т. п. — только из таблицы вариантов, которые знает клиент), `title`, `text` (ключ), `owned_badge` (bool). Страница `text` — то же без витрины, 16 строк.

### 3.2 Рецепт (`crafting`)

Рисуется из `Minecraft.getInstance().level.getRecipeManager().byKey(id)` (П2). Сетка 3 × 3 (форменный и бесформенный рецепт), стрелка, результат. Ингредиент с несколькими вариантами (тег) перебирается раз в секунду, как в JEI/IE. Клик по ингредиенту или результату — на его статью, если она есть. Нет рецепта на клиенте (линия выключена, датапак убрал) — страница пропускается; если в статье не осталось страниц — статья скрыта.

```
┌──────────────────────────────┐
│ Как сделать лупу             │
│                              │
│   ┌──┬──┬──┐                 │
│   │  │▒▒│  │   стекл. панель │
│   ├──┼──┼──┤        ┌──┐     │
```

### 3.3 Сцена «Стадии роста» (`scene`, на весь разворот)

Главная наглядная страница (В8). Вместо ленты картинок — **3D-сцена**: маленькая грядка из настоящих блоков мода, по шагам показывает, что даёт сбор на каждой стадии. Рамка страницы-сцены, управление и движок — §3.13 и §5.8. Блок `wildroots:wild_carrot` рисуется по своему blockstate (`stage` 0–5, `size` 0–3, `variant` 0–3, `ailing`): модели и спрайты стадий уже есть (`blockstates/wild_carrot.json`, `block/wild_carrot_stage*.png`), `BlockColor` у растения нет — цвет не зависит от BE, поэтому сцене достаточно blockstate.

**Структура `scene.carrot_stages`** (6 × 2 × 3): ряд пашни спереди — растения «из семени» на стадиях 0, 1, 2, 3; ряд сзади — посаженный маточник на стадиях 3, 4, 5; пустые клетки пашни между ними. Камера по умолчанию — три четверти спереди-сверху (yaw 200°, pitch 30°).

```
вид сцены (шаг 3 из 6):              схема структуры (сверху, y = 1):

        ✿·    ✿     ΨΨΨ                  z=2  .  .  .  M3 M4 M5   ← маточник
      ┌────┬────┬────┐                    z=1  .  .  .  .  .  .
   ,   ψ   ΨΨ  [ΨΨΨ]  ← рамка шага        z=0  S0 S1 S2 S3 .  .    ← из семени
 ─────────────────────                   y = 0 — пашня под всеми клетками
   ✋ ─► (морковь)(маточник) выпрыгивают
   «Корнеплод созрел · ждёт сбора»       S = из семени, M = маточник, цифра — stage
```

| Шаг | Что происходит в сцене | Подпись (смысл; текст ND) | Сбор по коду |
|---|---|---|---|
| 1 | Общий план, метки над рядами «Из семени» / «Маточник посажен» | Два ряда — два пути одного растения | — |
| 2 | Рамка на S0–S2; рука срывает S1 → выпрыгивает лот-сеянец, клетка становится пашней и снова S1 | Сорванное рано — вернутся те же семена | `stage < HARVEST_STAGE` → `LotStacks.seedling` |
| 3 | Рамка на S3, метка «ждёт сбора» (значок часов); рука срывает → выпрыгивают морковь и маточник | Корнеплод созрел и ждёт; сбор — еда и маточник | `food(...)` без `MOTHER`, затем `MotherItem.of` |
| 4 | Рука несёт маточник к M3; рамка на M3 | Посаженный маточник — то же растение | маточник на ст. 3 → только маточник |
| 5 | Рамка на M4 (цветение); пчела облетает зонтики M4–M5; сбор M4 → маточник назад | Цветёт только маточник; ему нужны опылители | `MotherItem.of` |
| 6 | Рамка на M5; рука срывает → выпрыгивает лот семян | Семена созрели: лот от опылителей | `seeds(...)` |

| Стадия | Ключ названия (морковь) | Сбор (не-маточник) | Сбор (посаженный маточник) | Код |
|---|---|---|---|---|
| 0 | `stage.seed` | лот-сеянец, те же семена | — | `HarvestService`: `stage < HARVEST_STAGE` → `LotStacks.seedling` |
| 1–2 | `stage.rosette` | лот-сеянец, те же семена | — | то же |
| 3 | `stage.harvest_ready.wild_carrot` | урожай (класс) + маточник; дальше не растёт, ждёт бесконечно (В2, В6) | только маточник | `food(...)` если нет `MOTHER`, затем `MotherItem.of` |
| 4 | `stage.flowering` | — (не доходит, В2) | маточник | `MotherItem.of` |
| 5 | `stage.seed_ripening` | — | лот семян (с отцами, если собрал игрок) | `seeds(...)` |

- Над каждым растением в шагах 2–6 — метка с названием стадии (ключи `wildroots.tooltip.stage.*`, narrative §3.4); наведение на метку — тултип «что происходит» (`wildroots.journal.scene.carrot_stages.stage.<n>`). Наведение на выпрыгнувший предмет — ванильный тултип, клик — его статья (П3).
- Чисел нет: «лот семян», а не число семян; номер стадии — только в данных.
- Сцена ведётся от вида (`species` в JSON). Для волн 2+ — своя структура и свои blockstate, тот же движок.
- **Запасной кадр** (§3.13): ряд спрайтов стадий с иконками сбора — то, что в v0.1 было 2D-лентой.
- **Зависимость:** если D1 не влит к началу WR-181l, сцена всё равно описывает поведение после D1 (это данные), а GameTest сверки (§5.7) включается вместе с D1.

### 3.4 Легенда шкалы признаков (`trait_legend`)

Учит читать панель лупы (В3). **Полосы рисует тот же виджет, что и панель лупы** — один класс `client.ui.TraitBar` (§5.4), чтобы игрок видел в журнале ровно то, что видит над пакетиком семян.

Стиль полосы (общий с панелью лупы): 5 сегментов 6 × 5 px с зазором 1 px (34 px). Заполнено столько сегментов, какова ступень 1–5 (`LensScale.step`, границы 0.20 / 0.35 / 0.55 / 0.75). ### 3.6 Сцена «Цикл двулетника» (`scene`, на весь разворот)

Ponder в миниатюре (В8): одно поколение моркови от посадки до нового лота на грядке 3 × 3. Здесь же видно, **зачем отбирать**: растения на стадии 3 разного размера (`size` 0–3), и в землю возвращаются крупные.

**Структура `scene.carrot_cycle`** (5 × 3 × 5): пашня 3 × 3 в центре, улей (`minecraft:beehive`) на углу, трава по краю. Камера — yaw 225°, pitch 35°.

|---|---|---|---|

### 3.7 Сетки: виды и коллекция сортов (`grid`)

### 3.9 Поиск

- Поле в полосе навигации; фокус — клик, `Ctrl+F` или просто начать печатать на оглавлении.
- Ищет по **показанному** тексту: заголовки и текст открытых статей и записей на языке клиента (после `I18n`, без разметки). Закрытое не ищется — поиск не спойлерит.
- Регистр и «ё/е» не различаются. Результаты — список «заголовок · категория» на развороте, до 32, сначала совпадения в заголовке. `Enter` — первый результат, стрелки — выбор.
- Индекс строится лениво при первом поиске и сбрасывается при `JournalSync` и смене языка.

### 3.10 Закладки

- Звезда в шапке записи ставит или снимает закладку. Закладки — лента под вкладками слева (до 8 видно, остальные — в оглавлении «Закреплено»).
- **Одно понятие для игрока, два хранилища:**
  - динамическая запись → `JournalAction PIN/UNPIN` (как v1; переживает смену компьютера, закреплённые подсказки по-прежнему сверху в «Заметках»);
  - статья руководства → локальный файл клиента `config/wildroots-journal-client.json`, по ключу мира или сервера, ≤ 16 закладок.
- Отдельная находка для SD: `09-security.md` (таблица лимитов capability) говорит «закреплённых ≤ 16», а `JournalData.apply` число закреплённых не ограничивает. Закрыть в WR-181f: `PIN` сверх 16 отвергается.

### 3.11 Назад / вперёд и клавиши

История — стек переходов (запись + разворот), до 32. Переход по ссылке, поиску, закладке, клику по иконке кладёт текущую страницу в стек.

| Действие | Мышь | Клавиатура |
|---|---|---|
| Листать | `◄` `►`, колесо над книгой (вне окна сцены) | `←` `→`, `PgUp` `PgDn`, `A` `D` |
| Назад / вперёд по истории | `◄◄` `►►`, боковые кнопки мыши 4 / 5 | `Backspace` / `Alt+←` / `Alt+→` |
| К родителю / оглавлению | `◄` в шапке / `⌂` | `Home` — оглавление |
| Поиск | поле | `Ctrl+F`, `Esc` очищает поле |
| Закладка | `★` | `Ctrl+D` |
| Сцена: шаг, пуск, поворот | §3.13 | `[` `]`, `Space`, `R`, `V` |
| Фокус элементов | — | `Tab` / `Shift+Tab`, `Enter` — нажать |
| Закрыть | — | `Esc`, клавиша инвентаря |

- Журнал **запоминает последнюю открытую страницу** до выхода из мира (как IE). Первое открытие и открытие после нового — на оглавлении.
- Экран не ставит игру на паузу (как v1).

### 3.12 Заметка-подсказка (`hint`)

Как v1 по данным, но компактно: на странице несколько коротких заметок (подсказка ≤ 3 предложений, narrative §1.2 п. 6), а не одна на страницу. Под каждой — «Подробнее →» на статью руководства (§4.3) и звезда закрепления.

| Действие | Мышь | Клавиатура |
|---|---|---|
| Пуск / пауза | `▶/⏸` | `Space` |
| Шаг назад / вперёд | `⏮` `⏭`, клик по точке шага на ползунке | `[` `]` |
| Перемотка внутри шага | тянуть ползунок | `Shift+[` `Shift+]` — ±1 с |
| Поворот | тянуть ЛКМ в окне: yaw — свободно, pitch — 10°…80° | `←` `→` `↑` `↓` при фокусе на окне |
| Масштаб | колесо в окне, 0.6×…2.0× (листание колесом над окном выключено) | `+` `-` |
| Сброс вида | двойной клик, `⟲` | `R` |
| Запасной 2D-кадр | `2D` (переключатель) | `V` |

- **Воспроизведение.** При первом открытии страницы сцена идёт сама с шага 1; в конце последнего шага — пауза и кнопка «↻ сначала» (без бесконечного цикла). Любое касание ползунка или шага ставит паузу. Подпись шага всегда видна текстом — сцену можно «прочитать», не глядя на анимацию.
- **Перемотка детерминирована.** Состояние блоков в начале шага N = структура + все `set_block` шагов 1…N−1, применённые сразу. Короткие эффекты (выпрыгнувший предмет, полёт пчелы, рука) проигрываются только в текущем шаге. Поэтому переход на любой шаг мгновенный и всегда даёт одну и ту же картинку.
- **Наведение.** Метки над блоками и выпрыгнувшие предметы дают тултип; клик по предмету — его статья (П3). Выбор блоков лучом в M1a не делаем.
- **Масштаб GUI 1–4.** Окно сцены задано в GUI-пикселях (264 × 112), поэтому при любом масштабе занимает ту же долю книги. Масштаб модели подбирается так, чтобы описанная сфера структуры влезала в окно при zoom 1.0. Предметы, значки и метки не мельче 8 GUI px; рамки подсветки — 1 GUI px. Наименьший экран 320 × 240 уже учтён размером разворота (§3.0).
- **Запасной 2D-кадр** — у каждой сцены. Показывается, когда: сцена не прошла проверку (§5.8); рендер бросил исключение (одна строка лога, сцена до конца сеанса — в 2D); клиентская опция `journalScenes = false` (слабое железо, укачивание, запись видео); игрок нажал `2D`. Кадр строится из того же JSON: у шага есть `frame` — до 8 иконок (предмет или спрайт блока) в ряд или по кольцу, со стрелками и подсветкой текущего шага, та же подпись и тот же ползунок шагов. Если и кадр не собрался — страница с подписями шагов текстом.

## 5. Ограничения и указания для SD

### 5.1 Клиент и сервер

- Весь журнал v2 — в пакете `..client.journal..` с `@OnlyIn(Dist.CLIENT)`; ArchUnit-правила `..client..` и проверка загруженных классов (WR-198) должны остаться зелёными. Сервер не знает о статьях руководства.
- **Данные — только существующие:** `ClientJournal` (записи `JournalSync`), `ClientDefinitions` (виды, сорта, `displayTraits`, жизненный цикл), клиентский `RecipeManager`, реестры блоков и предметов, модели и атласы, lang. 3D-сцены не используют `ClientLevel` (§5.8). Генетики на клиенте нет (архитектура §15).
- **C→S — только существующий `JournalAction`** (`MARK_READ`, `PIN`, `UNPIN`). Новых C→S пакетов нет. Обоснование против SEC-02 (корзина 5 шт., пополнение 5/с на игрока и тип): клиент ставит `JournalAction` в очередь и отправляет ≤ 4 в секунду; `MARK_READ` за запись — не больше одного раза за открытие экрана (как v1, `markedRead`); статья руководства шлёт `MARK_READ` за свои «новые» записи (обычно 1–3). Кнопки «прочитать всё» нет — она упёрлась бы в лимит.
- **S→C:** v2 в M1a не меняет `JournalSync`. M1b (WR-181i) добавляет вид записи `line.*` — расширение `JournalData.ID`, сериализация та же, лимиты те же (≤ 256 записей, ≤ 16 рядов, аргументы ≤ 64 кодовые точки); JUnit на декодер с новым видом и фаззинг WR-197 по нему.
- Сервер в WR-181f: лимит закреплённых ≤ 16 в `JournalData.apply` (таблица SEC-09). Других серверных правок нет.

### 5.2 Статичные данные

```
assets/wildroots/journal/
  categories/<id>.json   { "id", "icon": "<item id>" | "gui:<sprite>", "group": "guide", "order" }
  entries/<id>.json      { "id": "guide.cycle", "category", "icon", "order",
                           "unlock": ["hint.mother_plant"],          // пусто = всегда
                           "items": ["wildroots:mother_root"],       // для П3 и поиска по предмету
                           "see_also": ["guide.stages", "guide.pollination"],
                           "pages": [ { "type": "scene", "scene": "scene.carrot_cycle" },   // §5.8
                                      { "type": "spotlight", "item": "wildroots:mother_root",
                                        "text": "wildroots.journal.hint.mother_plant", "unlock": [] } ] }
  scenes/<id>.json       формат и лимиты — §5.8
  hint_links.json        { "hint.mother_plant": "guide.cycle", … }        // §4.3
```

- Типы страниц: `text`, `spotlight`, `crafting`, `scene`, `trait_legend`, `links` (`stage_strip` и `cycle` из v0.1 заменены сценами, В8; их 2D-вид — запасной кадр сцены). Динамические (`grid`, `species`, `cultivar`, `line`, `hint`) строятся кодом из записей сервера, в JSON их нет.
- Загрузка — клиентский `SimplePreparableReloadListener` (F3+T перезагружает книгу и сцены, удобно ND и TA).
- **Опции клиента** (`config/wildroots-client.toml`): `showAllGuides = false` (В4, §2.3), `journalScenes = true` (`false` — все сцены в запасном 2D-кадре, §3.13).
- **Ресурсы может подменить серверный ресурс-пак**, поэтому парсер ограничен и не падает: файл ≤ 32 КиБ, всего ≤ 256 КиБ, категорий ≤ 16, статей ≤ 256, страниц в статье ≤ 24, `unlock`/`items`/`see_also` ≤ 8, строки ≤ 128 символов, id — по шаблону `[a-z0-9_.]{1,64}`. Неизвестный тип страницы, неизвестный предмет, плохой JSON — страница или статья пропускается, одна строка в лог (с троттлингом, как `ID_WARN`). Текста в JSON нет — только ключи lang.
- Разметка ссылок `[[id|текст]]` разбирается один раз при сборке страницы; вложенность и другие команды не поддерживаются; ссылка на неизвестный id — обычный текст.

### 5.3 Масштаб, экран, вёрстка

- Разворот 288 × 180 + вкладки 12 + полоса 16 + поля — помещается в 320 × 240, то есть при любом масштабе GUI 1–4 и любом соотношении (16:9, 16:10, 4:3, 21:9). Книга по центру, вкладки слева от книги.
- Вёрстка (перенос строк `font.split`, разбиение на страницы, положение иконок) считается **один раз** при открытии, `JournalSync`, смене размера окна или языка — не каждый кадр. Кадр только рисует готовые строки и спрайты.
- Перенос не режет абзац по середине, если остаток ≤ 2 строк (переносит абзац целиком); заголовок не остаётся последним на странице.
- Шрифт — ванильный (поддерживает кириллицу и Unicode-шрифт игрока). Цвета — константы в одном классе, текст без тени.

### 5.4 Общий виджет полосы признаков

`client.ui.TraitBar` — один класс для журнала и для панели лупы (В3): `draw(GuiGraphics, x, y, step 1–5, scaleKey)`, спрайты из `trait_bar.png`, слово справа. Если панель лупы делается раньше, журнал берёт её виджет; если позже — панель лупы берёт этот. Владелец задачи, кто первый, выносит виджет в `client.ui`.

### 5.8 3D-сцены: формат, рендер, бюджеты, безопасность

**Формат** (`assets/wildroots/journal/scenes/<id>.json`, ссылается страница `{"type": "scene", "scene": "scene.carrot_cycle"}`):

```
{ "id": "scene.carrot_cycle", "species": "wildroots:wild_carrot",
  "size": [5, 3, 5],                                       // x, y, z — блоков
  "palette": { "f": "minecraft:farmland[moisture=7]", "g": "minecraft:grass_block",
               "h": "minecraft:beehive[facing=south]",
               "c": "wildroots:wild_carrot[stage=0,size=0]", ".": "minecraft:air" },
  "layers": [ ["ggggg", "gfffg", "gfffg", "gfffg", "ggggh"], ["....." …], ["....." …] ],  // y снизу вверх, строки по z
  "camera": { "yaw": 225, "pitch": 35, "zoom": 1.0 },
  "steps": [
    { "caption": "wildroots.journal.scene.carrot_cycle.1", "duration": 80, "unlock": [],
      "camera": { "yaw": 210, "pitch": 30, "zoom": 1.2, "ease": 20 },                  // необязательно
      "actions": [
        { "at": 0,  "type": "icon",      "icon": "hand_lot", "path": [[0,2,1], [4,2,3]], "ticks": 40 },
        { "at": 5,  "type": "set_block", "pos": [1,1,1], "state": "wildroots:wild_carrot[stage=0,size=2]" },
        { "at": 60, "type": "label",     "pos": [2,2,2], "key": "wildroots.tooltip.stage.seed" } ],
      "frame": [ { "item": "wildroots:seed_lot" }, { "sprite": "wildroots:block/wild_carrot_stage0" } ] },
    { "caption": "…", "duration": 100, "actions": [
        { "at": 10, "type": "pop_item",  "pos": [1,1,1], "item": "wildroots:mother_root" },
        { "at": 10, "type": "highlight", "from": [1,1,1], "to": [1,1,1] },
        { "at": 30, "type": "bee",       "path": [[4,2,4], [1,2,1], [3,2,3], [4,2,4]], "ticks": 80 } ] } ] }
```

| Действие | Что делает | Постоянное (входит в перемотку) |
|---|---|---|
| `set_block` | Ставит blockstate в клетку (рост, сбор → воздух/пашня, посадка) | да |
| `pop_item` | Предмет выпрыгивает из клетки по дуге, повисает с покачиванием до конца шага; `variant` — из таблицы вариантов показа (§3.1) | нет |
| `icon` | Значок-билборд (`hand`, `hand_lot`, `hand_brush`, `clock`, `arrow_loop`) движется по пути | нет |
| `bee` | Модель пчелы (`BeeModel` из `EntityModelSet` с ванильной текстурой, **без сущности**) летит по пути, крылья машут | нет |
| `label` | Подпись-выноска над клеткой (ключ lang), с тултипом | нет |
| `highlight` | Рамка вокруг клеток `from…to` | нет |
| шаг `camera` | Плавный перевод камеры за `ease` тиков; игрок может повернуть сам — тогда до конца шага камера его | — |

**Рендер — свой, без зависимостей и без настоящего мира:**

- `SceneBlockGetter implements BlockAndTintGetter` — только для чтения над массивом `BlockState[]` размера сцены: `getBlockEntity` → `null`, свет — полный постоянный, тинт — цвета равнин (трава, листва), `getShade` — как в мире. Никакого `ClientLevel`, `Level`, чанков, тиков, сущностей: сцене нечего «утечь» в мир и нечем его тронуть.
- Сетка строится через `BlockRenderDispatcher.renderBatched(...)` по типам рендера (`solid`, `cutout`, `cutout_mipped`, `translucent`) в `BufferBuilder` и загружается в `VertexBuffer` (≤ 4 на сцену). Пересборка — только когда меняется блок (`set_block`, перемотка), не каждый кадр.
- Отрисовка в GUI: `enableScissor` по окну, сдвиг по z поверх страницы, поза — перенос в центр окна, масштаб, pitch, yaw; `Lighting.setupFor3DItems`. Предметы — `ItemRenderer` в той же позе; значки и метки — 2D поверх по проекции точки клетки.
- Время — тики экрана (20/с) с интерполяцией `partialTick`; на паузе ничего не пересчитывается.
- Живёт **одна сцена** — на открытом развороте. Перелистнули, закрыли журнал, сменили ресурс-пак — `VertexBuffer` закрываются. Анимации и тики сцены не идут, когда её не видно.
- Весь рендер сцены — в `try/catch` по кадру: исключение → запасной кадр (§3.13), одна строка лога, без краша игры. Модели и текстуры — из ресурс-паков игрока, как у любого блока.

**Жёсткие лимиты** (сцену может подменить серверный ресурс-пак; проверка при загрузке, до построения сетки; нарушение → сцена не загружается, страница показывает запасной кадр или подписи):

| Что | Лимит |
|---|---|
| Файл сцены | ≤ 16 КиБ; всего сцен ≤ 32, всех файлов сцен ≤ 256 КиБ |
| Размер структуры | каждая ось 1…7, объём ≤ 7 × 5 × 7 = 245 клеток |
| Палитра | ≤ 16 записей, ключ — 1 символ; blockstate-строка ≤ 128 символов, разбор `BlockStateParser` только по реестру блоков; неизвестный блок или свойство → воздух и одна строка лога |
| Запрещено в палитре и `set_block` | блоки с BE (`EntityBlock`), NBT в любом виде, жидкости-источники с тиками — заменяются воздухом |
| Шаги | ≤ 16; `duration` 10…400 тиков; сцена целиком ≤ 2400 тиков (2 мин) |
| Действия | ≤ 16 на шаг, ≤ 128 на сцену; `at` в пределах шага; `set_block` ≤ 64 на сцену |
| Пути | ≤ 8 точек; все координаты в границах структуры с запасом 1 клетка |
| Одновременно в кадре | ≤ 12 выпрыгнувших предметов, ≤ 4 пчелы, ≤ 4 значка, ≤ 8 меток |
| Камера | yaw любой (по модулю 360), pitch 10…80, zoom 0.6…2.0 — вне диапазона прижимается |
| Тексты | только ключи lang (`caption`, `key`); литерального текста нет |
| Предметы | id из реестра, `variant` — только из таблицы клиента; без NBT |
| `unlock` шага | те же правила, что у страниц (§2.3), ≤ 8 id |

**Бюджеты сцены:**

| Что | Бюджет |
|---|---|
| Кадр экрана со сценой | ≤ 1.5 мс (сетка ≤ 245 блоков + ≤ 12 предметов + ≤ 4 пчелы); без сцены — по-прежнему ≤ 0.5 мс |
| Пересборка сетки | ≤ 3 мс за `set_block` или перемотку; не чаще раза в тик |
| Память | ≤ 2 МиБ GPU и ≤ 1 МиБ кучи на живую сцену; живая сцена одна |
| Загрузка и проверка всех сцен | ≤ 20 мс при перезагрузке ресурсов |
| JSON сцен в jar | ≤ 32 КиБ для M1a (2 сцены), входит в бюджет JSON руководства (§5.5 поднят до 96 КиБ) |

Измерение — `runClient`, F3-график кадра и счётчики в debug-режиме журнала (число пересборок, время сборки сетки).

Против v0.1 (13.5 д) — **+5 д** за 3D-сцены (В8): движок WR-181k 3.5 д, сцены WR-181l 1.5 д, арт +0.5 д, проверка +0.5 д; WR-181d урезана с 2 д до 1 д (2D-ленты и схема стали запасным кадром). Критический путь при одном SD — 13 д; при двух SD (второй берёт k → l после b) — a → b → k → l ≈ 8 д, параллельно c → e → f → d ≈ 5 д.

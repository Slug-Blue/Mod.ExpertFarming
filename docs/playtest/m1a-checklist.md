# Плейтест M1a: ручная сессия (WR-195)

Что не покрывает автоматика шлюза M1a (`M1aGateGameTests`, `ci/perf-bench.sh`) и что проверяет владелец или тестер руками. Ссылки: GDD §11.3 (хронометраж), §11.4 (чек-лист онбординга), §12.4 (темп); `00-vision.md` метрики 1 и 3; `docs/STATUS.md` («Не проверено (`runClient`)»); `docs/06-tasks.md` WR-195.

Сборка: ветка с WR-195 (или `main` после слияния), `JAVA_HOME=<JDK 17> ./gradlew :mod:runClient`. Новый мир «Выживание», тип мира «Обычный», без читов, сид случайный (записать). Журнал, лупа, пчёлы — как придут в игре. **Никаких команд, креатива и F3+N** до раздела 3.

## 3. MSPT с живым клиентом (`runServer` + клиент)

Стенд WR-028 меряет сервер без игроков: пакеты обновления блоков (`ClientboundBlockUpdatePacket` / `SectionBlocksUpdate`) и загрузка чанков с тысячами BE не покрыты (S9, WR-195).

1. `./gradlew :mod:runServer` (EULA в `mod/run/eula.txt` принимает владелец), дождаться строки `Done`.
2. Клиент `runClient` → «Сетевая игра» → `localhost`. Оператор: `op <ник>` в консоли сервера.
3. Поле: ≈ 1 000–2 000 растений моркови на пашне в 2–4 чанках рядом с игроком (креатив, лоты), часть цветёт; пчёлы рядом. Контроль: та же площадь пшеницы в другом месте.
4. Стоя у поля моркови: `/debug start`, 2 минуты, `/debug stop` → записать среднее MSPT из отчёта (`debug/profile-results-*.txt` в папке сервера). То же у поля пшеницы и на пустой пашне.
5. Отойти на 200+ блоков и вернуться (выгрузка и загрузка чанков поля): заметить подвисание, записать MSPT из `/debug`.

|---|---|---|

| Пшеница | | |
| Морковь (≈ ____ растений) | | |

Порог: прирост моркови против пшеницы ≤ 2 мс (предупреждение > 0.5 мс), как у стенда (`00-vision.md` метрика 3).

## 4. Мультиплеер: 2 клиента на выделенном сервере (WR-198)

Автоматика (CI): `runGameTestServer` — выделенный сервер, весь набор проходит; `DedicatedServerGameTests` проверяет, что ни один класс `wildroots.client` не загружен; ArchUnit `modClientOnlyFromLambdas` и `noClientCodeOutsideClientPackage` держат код в этой форме. Здесь — то, что видят только живые клиенты: рассинхрон между двумя игроками.

Подготовка:
1. `./gradlew :mod:runServer` (EULA в `mod/run/eula.txt` принимает владелец), дождаться `Done`. В `server.properties`: `online-mode=false` (два dev-клиента), `difficulty=peaceful`.
2. Два клиента: `./gradlew :mod:runClient` дважды (второй — с `--args "--username TesterB"`, первый — `TesterA`), оба → «Сетевая игра» → `localhost`. В консоли сервера: `op TesterA`.
3. Общая грядка 6×6 пашни у воды; у каждого игрока лоты (`/give` или из патча), кисть (если есть в сборке) и лупа.

Сессия 30 минут (`/time set day`, при необходимости `/gamerule randomTickSpeed 30` на ускорение — записать значение):

| Шаг | Что сделать | Ожидание | Итог (✓/✗, время, заметки) |
|---|---|---|---|
| 1 | A и B по очереди сажают лоты в соседние клетки одной грядки | У обоих одни и те же растения в тех же клетках, ни одного «призрака» (у одного есть, у другого нет) | |
| 2 | Оба стоят у грядки 10 минут роста | Стадии совпадают у A и B на каждой клетке (сверять вслух по 3–4 клеткам раз в 2 минуты) | |
| 3 | A и B смотрят лупой на одно растение | Одинаковые строки у обоих; повторный клик в тот же тик не даёт второго осмотра | |
| 4 | Кисть: A, затем B опыляют одно цветущее растение (в сборке M1a кисти ещё нет — шаг пропустить и отметить «нет кисти») | Побеждает последняя кисть: лот после сбора несёт отца от B | |
| 5 | A сажает, B собирает; затем наоборот | Урожай у собравшего; статус сорта (если сорт распознан) засчитан посадившему, запись в журнале у посадившего | |
| 6 | Один выходит и заходит обратно посреди роста | После входа стадии совпадают с теми, что видит второй; журнал и мешочек на месте | |
| 7 | Оба одновременно ломают и сажают в одной клетке (10 попыток) | Ни одного дубля семян, ни одного растения без блока; в логе сервера нет `packet_failed` и исключений | |
| 8 | Конец: остановить сервер командой `stop`, запустить снова, оба заходят | Грядка как перед остановкой: те же растения и стадии | |

Записать: версия (коммит), длительность, `randomTickSpeed`, найденный рассинхрон с координатами и скриншотами обоих клиентов, хвост `mod/run/logs/latest.log` при ошибке.

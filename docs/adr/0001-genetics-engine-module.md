# ADR-0001: Генетический движок — подпроект на чистой Java с детерминированным RNG

## Статус
Предложено (2026-10-29)
Ревизия 1 (2026-10-29, threat model SEC-25, SEC-30): в ключи RNG потомка, шума, ленивых лотов и выбора отцов входит секрет мира `wildroots_secret`; функции движка тотальны на валидированных входах.

## Контекст
Генетика — ядро мода: рекомбинация, мутации, фенотип `P = clamp(G_eff·V + E + ε)`, компромиссы (GDD §3.10), классификация сортов, дикие и деревенские популяции, качество урожая и переработки. Правила сложные, их много раз будут тюнить, и они должны быть детерминированы от seed (GDD §3.8, §9.5, worldgen §3.3). Тесты с запуском Minecraft медленные и хрупкие. Если генетика перемешается с кодом Forge, тестировать баланс и инварианты («нет растения с `P ≥ 0.75` по трём осям») можно будет только в игре.

## Решение
- Отдельный Gradle-подпроект `:genetics` (`java-library`, Java 17) **без зависимостей** — без `net.minecraft`, Forge, Gson и DFU. Чистоту гарантирует компилятор.
- Мод-слой (`:mod`) общается с движком только через фасад `GeneticsService` и неизменяемые записи (`SpeciesDef`, `CultivarDef`, `Environment`, `LotRecord`, `Genome`, `Phenotype`…). Разбор JSON, сбор среды из клетки, хранение в NBT и BlockEntity остаются в мод-слое.
- Валидация определений и нейтральный кодек генома (`GenomeRecord`, миграции) — тоже в движке, поэтому они тестируются JUnit.
- Свой RNG: `SplitMix64`, `Hash64` (FNV-1a 64 для строк и финализатор SplitMix для смешивания), свой Box–Muller. `java.util.Random`, `SplittableRandom` и `String.hashCode` в генетике запрещены. Эталонные последовательности закреплены тестом.
- **Секрет мира** (ревизия 1): `SavedData` `wildroots_secret` (`long` из `SecureRandom`) входит в ключи `Hash64(secret, lotId, remainingCount, packedPos)` (потомок), `…, "noise"` (шум), `Hash64(secret, lotId)` (ленивый лот), `Hash64(secret, plantUid, cycleIndex)` (отцы). Движок получает его как обычный аргумент. Секрет не уходит клиенту и в логи. Ключи worldgen и деревень остаются на `worldSeed`. Цель: геном лота, видимый модифицированному клиенту, не превращается в оракул потомства.
- Классы `:genetics` упаковываются в jar мода; в dev-запусках подключаются через `minecraft.runs.<run>.mods { wildroots { source … } }`.

## Альтернативы
1. **Пакет внутри мода + правило ArchUnit «без `net.minecraft`».** Проще в сборке, но чистота держится на тесте, а не на компиляторе, и тесты движка тянут classpath Minecraft. Остаётся запасным путём, если подпроект не заработает в ForgeGradle 6 (spike S7).
2. **Отдельный jar-in-jar (`jarJar`).** Лишний артефакт и версия без пользы: движок не переиспользуется вне мода.
3. **Генетика прямо в BlockEntity и предметах.** Быстрее старт, но баланс и миграции нельзя тестировать без игры, и логика размазана.

## Последствия
- Плюсы: быстрые JUnit-тесты баланса и инвариантов; порт канонической модели темпа GDD §12.5 на настоящий движок; детерминизм не зависит от JDK.
- Минусы: слой перевода JSON → записи движка (дублирование схемы Codec ↔ record), чуть сложнее Gradle.
- Риск: настройка нескольких источников в ForgeGradle 6 — проверяется spike'ом S7.

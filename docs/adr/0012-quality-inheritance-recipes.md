# ADR-0012: Наследование качества в переработке; FD с запасным путём

## Статус
Предложено (2026-10-29). Факт о котле FD — `[ПРОВЕРИТЬ]` (spike S6).
Ревизия 2 (2026-10-31, spike S5, `docs/spikes/S5-furnace-quality.md`): печь вызывает `assemble` (патч Forge), но выходной слот сравнивает без NBT, и классы сливаются. Решение изменено: защита в `matches` вместо mixin M3 (M3 — запасной). `quality_shaped` в верстаке подтверждён; книга рецептов не раскладывает ингредиенты с NBT. Принято в части ванильных станций; FD ждёт S6.
Ревизия 3 (2026-10-31, ответ владельца `00-vision.md` п. 25, GDD §6.7, §19.7): сноп сена с состояниями — свой блок `wildroots:hay_bale` без BE, правило выхода `straw_output` в `quality_shaped`, урон через `fallOn`, корм через события, горючесть через `IForgeBlock`, сигнальный дым без mixin (`05-architecture.md` §12.6).
Ревизия 4 (2026-10-31, ответ владельца `00-vision.md` п. 26): ванильного снопа в мире после линии пшеницы не остаётся — однократная конверсия чанка (палитра секций, очередь ≤ 4 чанка за тик, маркер `hay_done`): открытое место → `coarse`, помещение → `soft` (правило — трактовка оркестратора, `STATUS.md`); то же правило — при поломке и установке ванильного снопа.

## Контекст
Владелец (п. 14): переработанные продукты отражают сырьё. GDD §6.6: продукты с ванильными механиками сохраняют ванильный id и несут `wildroots:grade`; формула — среднее основных входов, потолок по ступени, бустеры +1. Нужно покрыть верстак, печь, коптильню, костёр и FD (разделочная доска, котёл). Хук в FD может оказаться хрупким; дефолт владельца — FD-блюда без класса.

## Решение
- Свои сериализаторы `wildroots:quality_shaped`, `quality_shapeless`, `quality_smelting`/`_smoking`/`_campfire`, наследующие ванильные классы. Ванильные рецепты перекрываются по их же id в пакетах линий; ингредиенты — теги; класс считается в `assemble` через движок. `matches = false`, если выход по классу 0.
- Роли входов — в JSON рецепта (`quality_inputs`, `boosters`, `output_by_grade`) или из реестра `quality_roles`.
- Печь: `canBurn`/`burn` сравнивают выход без NBT (`isSameItem`; `is(Item)` + `grow`; S5). `quality_smelting`/`_smoking` в `matches` отказываются плавить, пока в выходном слоте лежит тот же предмет другого класса (контейнер в `getRecipeFor` — сам BE, слот 2 виден). Печь ждёт, пока результат заберут. M3 — запасной путь, если защита конфликтует с чужими рецептами на тот же вход. `_campfire` защиты не требует: костёр роняет результат.
- Еда ванильных id с классом — mixin M2 в `FoodData.eat`; наши предметы — переопределение `getFoodProperties`.
- Торт и блок арбуза — без класса.
- **Сноп сена (ревизия 3):** перекрытие `minecraft:hay_block` в пакете линии пшеницы — `quality_shaped` с полем `straw_output`: худшая ступень входов и `floor` среднего класса → одно из 4 состояний (`brittle`/`coarse`/`soft`/`select`), результат — предмет состояния без класса. Блок `hay_bale extends HayBlock` со свойством `straw`, без BE; ванильный `hay_block` не перекрывается в реестре (по поведению равен `soft`), но в мире конвертируется в наш (ревизия 4). Урон — `fallOn` с множителем состояния; корм лошадей и лам — события (§12.4); горючесть — `IForgeBlock#getFlammability`/`getFireSpreadSpeed` по состоянию `[ПРОВЕРИТЬ]` (запасной путь — отдельные блоки на `coarse`/`brittle` с `FireBlock#setFlammable`); сигнальный дым — событие установки костра и запланированный тик, без mixin. Разбор снопа отключён.
- FD: разделочная доска — данными (`forge:partial_nbt` + `forge:difference`), классы 1–2 → 1 ломтик, 3–4 → 2. Котёл — **по умолчанию без класса**; подкласс `CookingPotRecipe` включается флагом `fdDishQuality`, только если S6 покажет, что котёл вызывает `assemble` и не сливает буфер без NBT.

## Альтернативы
1. **`PlayerEvent.ItemCraftedEvent`** — ставить класс после крафта. Класс не виден в слоте результата, ненадёжно при Shift-клике и в автокрафтерах. Отклонено.
2. **Обёртка всех рецептов кодом при загрузке.** Хрупко, меняет чужие рецепты непредсказуемо. Отклонено.
3. **Mixin в `CookingPotBlockEntity` FD.** Самый хрупкий вариант (внутренний код стороннего мода). Отклонено.

## Последствия
- Плюсы: класс виден до крафта; работает с автокрафтерами; FD-интеграция в MVP почти без кода.
- Минусы: перекрытие ванильных рецептов конфликтует с модами, перекрывающими те же id (выигрывает пакет, вставленный в мир позже: `Position.TOP` действует только в момент вставки, S1); JEI и книга рецептов показывают результат как «добротный».
- Книга рецептов не раскладывает ингредиенты с классом (`ServerPlaceRecipe` + `Inventory#findSlotMatchingUnusedItem` → `isSameItemSameTags`, S5): игрок кладёт их в сетку вручную. Ограничение ванили, mixin его не обходит.
- Вход, положенный в заблокированную защитой печь, готовится 200 тиков вместо значения рецепта (косметика).
- Автокрафтеры модов (Create, AE2, RS) не проверены: новые зависимости в spike не подключались.
- Сноп сена (ревизия 3): 4 предмета вместо одного; ванильные проверки корма и дыма жёстко ссылаются на `Blocks.HAY_BLOCK`, поэтому корм и дым идут через события, а снопы вне перекрытых списков процессоров закрывает однократная конверсия чанка (ревизия 4) — это единственный проход по блокам чанка в моде, он ограничен палитрой секций и бюджетом очереди.

# ADR-0008: Транзиентный индекс цветения; отцы собираются при завязывании

## Статус
Предложено (2026-10-29)

## Контекст
GDD §4.1: опыление — событие, а не тик; кандидаты — цветущие растения того же вида в радиусе вида (до 8 у теосинте, ±2 по Y), не больше 64 кандидатов и 4 отцов. Периодическое сканирование запрещено (§13). Дикие статичные патчи должны участвовать в опылении (worldgen §12.2).

## Решение
- `BloomIndex` на каждом `ServerLevel`, только в памяти: `Long2ObjectOpenHashMap<ChunkPos, Int2ObjectOpenHashMap<speciesIndex, LongArrayList<pos>>>` (fastutil из Minecraft).
- Добавление: вход в стадию цветения и `onLoad` цветущей BE. Удаление: выход из цветения, `setRemoved`, `onChunkUnloaded`, выгрузка уровня. На диск индекс не пишется и восстанавливается сам.
- Завязывание (один раз за цикл): обход ≤ 4 чанков по кругу радиуса, фильтр по Y, reservoir sampling ≤ 64, чтение BE только загруженных чанков, **копирование геномов отцов по значению** в «ожидающий лот» BE, выбор отцов в движке.
- Индекс читают и пчёлы (ADR-0009) — для выбора цели без сканирования.

## Альтернативы
1. **Сохраняемый индекс (SavedData).** Риск рассинхрона с блоками, лишняя запись на диск. Отклонено.
2. **Поиск по блокам в радиусе при завязывании.** Для радиуса 8 — до 17×17×5 ≈ 1 400 чтений на событие; терпимо, но масштабируется хуже и не годится для пчёл. Отклонено.
3. **Ссылки на отцов по позиции вместо копии генома.** Отец мог быть сломан к моменту сбора (GDD §14). Отклонено.

## Последствия
- Плюсы: O(1) на поддержку, ≤ 64 проверок на событие, нет данных на диске.
- Минусы: растения в незагруженных соседних чанках не опыляют — это ожидаемо и совпадает с поведением загрузки чанков.
- Стоимость: ≈ 20–50 мкс на завязывание.

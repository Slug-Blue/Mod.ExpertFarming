# ADR-0002: Кодирование генома и версионирование сохранений

## Статус
Предложено (2026-10-29)
Ревизия 1 (2026-10-29, threat model SEC-09, SEC-10): длина `a` ровно `layout.longCount ≤ 8`; декодер типобезопасен, без исключений, возвращает `Valid | Inert`; размер проверяется до разбора; превышение лимита → инертный объект без удаления сырого тега и без его копирования.
Ревизия 2 (2026-10-31, spike S10, `docs/spikes/S10-genome-migration-pouch.md`): `layoutHash` — 64 бита вместо FNV-1a 32 (коллизия 32-битного хэша находится перебором за 284 041 раскладку, и миграция молча декодировала бы чужой раскладкой); словарь индексируется `(вид, lh)` и хранит каноническую строку; записана политика сужения аллелей и миграция вложенных геномов. Механизм миграции подтверждён: 0 потерянных аллелей на 100 000 случайных миграций и на 290 геномах через save/load BE. Принято.

## Контекст
Геном живёт в тысячах BlockEntity и в предметах. GDD §3.1 требует компактности (< 64 байт на растение). Число локусов задаёт JSON вида, и его могут поменять наш баланс между волнами или автор датапака. Формат NBT тоже будет меняться от релиза к релизу. Обязательное требование фазы: старое сохранение грузится, и это покрыто тестом.

## Решение
- **Раскладка** (`GenomeLayout`) выводится из `SpeciesDef` в каноническом порядке (количественные по id → груз → качественные по id). Аллели упакованы в `long[]`: количественный 2 бита, груз 1, качественный 1, многоаллельный `ceil(log2 n)`. Морковь — 142 бита (`long[3]`).
- **NBT генома:** `{v, sp, lh, a}`: версия формата кода, вид, `layoutHash` — 64 бита (`LongTag` `lh`, FNV-1a 64 канонической строки раскладки; ревизия 2), `LongArrayTag`. Каноническая строка включает число аллелей качественного признака. Словарь раскладок индексируется `(вид, lh)` и хранит каноническую строку; если `lh` совпал с другой строкой того же вида, определение вида отклоняется с ошибкой загрузки (S10). Геном отца в лоте хранится компактно — `{lh, a}`, вид и `v` берутся из лота (ADR-0007, ревизия 2). Шум `ε` хранится отдельно в BlockEntity (`byte` на признак).
- **Две оси версий:**
  1. Формат кода — поле `v` в каждом сохраняемом корне (геном, BlockEntity, лот, мешочек, capability журнала, SavedData), цепочка мигратеров `vN → vN+1`, запись всегда в текущем формате.
  2. Данные вида — `lh`. При несовпадении старая раскладка берётся из словаря: история встроенных видов в jar (`data/wildroots/genome_layouts/`) и `SavedData` `wildroots_layouts` мира. Аллели перекодируются по `(признак, локус, аллель)`; новые локусы заполняются фоновыми частотами по `Hash64(genomeKey, traitId, locus, allele)`, удалённые отбрасываются с предупреждением. Сужение числа аллелей и смена типа признака заменяют значения вне нового диапазона фоном с предупреждением — единственная допустимая потеря (ревизия 2). Мигрируются все геномы корня, в том числе отцы лота и записи мешочка.
- **Защитные правила:** `v` из будущего или неизвестный вид → сырой NBT сохраняется без изменений, объект инертен. Данные никогда не удаляются молча.
- **Тесты:** golden-фикстуры всех выпущенных версий (JUnit в движке и в мод-слое) и GameTest-шаблоны `old_save_vN` на каждый релиз, которые никогда не удаляются.
- **CI-проверка:** изменилась раскладка встроенного вида без записи в истории → сборка красная.

## Альтернативы
1. **Самоописывающий NBT по признакам** (`{yield: [...], …}`). Миграция тривиальна, но ≈ 300 байт на геном против 24–40, а мешочек с 32 лотами по 5 геномов становится ≈ 50 КБ в пакетах контейнеров. Отклонено.
2. **Только `v` без `lh`, «локусы после выпуска не меняются».** Просто, но запрещает тюнинг, и любой датапак, поменявший число локусов, портит миры. Отклонено.
3. **DataFixerUpper.** Forge не даёт модам удобно регистрировать схемы DFU, а для пары полей это избыточно.

## Последствия
- Плюсы: компактно; изменение баланса не ломает миры; переносы предметов между мирами деградируют мягко (неизвестная раскладка → пересоздание диких секций и предупреждение).
- Минусы: словарь раскладок и история в jar — дополнительная дисциплина релиза (её держит CI). 64-битный `lh` — +4 байта на геном (ревизия 2).
- Сужение числа аллелей многоаллельного локуса или смена типа признака в JSON теряют значения вне диапазона (с предупреждением в лог). Авторы баланса и датапаков должны об этом знать.
- Изменение числа локусов признака меняет `G` существующих растений (новые локусы дикие) — это решение баланса, а не баг; Game Designer должен об этом знать.

# ADR-0009: Пчёлы — своя цель через события и capability пыльцы; mixin только запасной

## Статус
Предложено (2026-10-29). Работоспособность проверяет spike S2.
Принято (2026-10-31): S2 подтвердил путь без mixin (`docs/spikes/S2-bee-goal.md`): `Mob#goalSelector` публичен, AT `Bee#setHasNectar` (`m_27919_`) работает, `ForgeCaps` переживают улей, конфликта целей нет (0 зависаний за 3 игровых дня). Уточнение: окно свежести пыльцы считается в тиках вне улья — дефолт, ответа владельца нет (2026-10-31).

## Контекст
Владелец (п. 2): пчёлы переносят пыльцу между растениями одного вида. GDD §4.3: визит откладывает донора, если пчела несёт свежую пыльцу того же вида (≤ 2 визитов, ≤ 1200 тиков); нектар и мёд работают как обычно; ванильный бонус роста не распространяется. Ванильный `BeePollinateGoal` выбирает цели по тегу `#minecraft:flowers`, а он не различает состояния блока (стадию цветения) и виды. Задание: mixin только если без него никак.

## Решение
- `EntityJoinLevelEvent` (сервер) добавляет каждой `Bee` цель `BeeCropPollinateGoal` с приоритетом ванильной цели опыления (4). `Mob#goalSelector` — `public final`, AT не нужен. Событие срабатывает и при выходе из улья (пчела выходит новой сущностью с новым UUID), поэтому дубль цели отсекается проверкой `getAvailableGoals()`; ссылки на пчёл по UUID не хранятся.
- Цель стартует, только если пчеле нужен нектар и `BloomIndex` чанка пчелы и соседних (радиус ≈ 5) содержит цветущее растение вида с `bees` в JSON. Иначе работает ванильная цель.
- Визит: подлёт, зависание, затем `PollinationService.beeVisit`: донор в BE (вес 2.0, вытесняется старейший), смена пыльцы, `setHasNectar(true)` (AT `public net.minecraft.world.entity.animal.Bee m_27919_(Z)V`, подтверждено S2). `tick()` цели идемпотентен после визита.
- Пыльца хранится в capability `BeePollen` на сущности и переживает улей вместе с `ForgeCaps` (подтверждено S2: `removeIgnoredBeeTags` их не вырезает). Возраст пыльцы считается в тиках жизни пчелы **вне улья** (растёт в `LivingTickEvent`): по мировому времени окно 1200 тиков недостижимо, потому что пчела с нектаром сидит в улье ≥ 2400 тиков. Дефолт, ответа владельца нет (2026-10-31); после ответа правится GDD §4.3.
- Наши блоки не входят в `#minecraft:flowers` и `#minecraft:bee_growables`.

## Альтернативы
1. **Добавить блоки в `#minecraft:flowers`.** Пчёлы летели бы на нецветущие стадии и на виды без `bees`; события «визит завершён» нет, донора не отложить. Отклонено.
2. **Mixin в `Bee.BeePollinateGoal`** (предикат цели + хук завершения). Работает надёжно, но лезет во внутренний класс, где уже сидят другие моды пчёл. Запасной путь (M5), если две цели конфликтуют.
3. **Своё сканирование цветов пчелой.** Запрещено GDD §13.

## Последствия
- Плюсы: без mixin; стоимость — запрос к индексу; ванильные цветы и мёд не затронуты.
- Минусы: две цели опыления у пчелы могли бы спорить за движение. S2: при равном приоритете и флаге `MOVE` цели друг друга не вытесняют, работает стартовавшая первой; M5 не нужен.
- Окно пыльцы «вне улья» — отклонение от буквы GDD §4.3, ждёт подтверждения GD (`05-architecture.md` §21 п. 13).
- Трактовку «поиск через индекс ≠ сканирование» должен подтвердить Game Designer (`05-architecture.md` §21).
